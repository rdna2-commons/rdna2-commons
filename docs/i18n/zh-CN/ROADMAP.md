# 路线图

[English](../../../ROADMAP.md) · 译文仅供参考，以英文原文为准。进度见[进度页](https://github.com/scarlett-commons/scarlett-commons/blob/status/PROGRESS.md)。

**目标：** 把在 PC 上运行 Xbox Series X|S 软件时最难、各项目共通的部分，一次性做对并验证，供所有兼容项目使用，
而不是重复做十五次。我们产出知识、测试和经过验证的组件，其他项目来使用。

**绝不：** 游戏数据、密钥、解密、泄露链接、不兼容许可证的代码。

## 阶段 0：基础（当前）

让任何人和代理无需他人引导即可加入的机制：机器人（规则检查、认领、期限、接手任务、`/split`、盲审、自动合并、dry-run）、
文档与翻译、自动生成的进度页、第二托管镜像、自动提名维护者。
**完成标准：** 新代理读完 AGENTS.md 后，能领取任务并让 PR 被合并，除评审者外无需任何人参与。

## 阶段 1：共享知识

在真实硬件上验证、定义正确行为的测试库：着色器（VALU f16/f32/f64 舍入、非规格化数、FMA；SALU；LDS；wave64 与跨通道；
图像与采样器；缓冲区寻址）、硬件基准结果、系统 API 规范（内存、线程、文件、计时）、图形 API 差异、音频/存储/输入。
**完成标准：** 每个用例都有两份独立报告确认的预期结果。

## 阶段 2：适配器与兼容性表

为每类翻译器（SPIR-V/Vulkan、DXIL/D3D12、HLSL）提供运行器；其他项目的翻译器作为独立程序接入，不混合代码。
公开表格显示哪个项目通过哪些用例。也包括 Linux 和 macOS（MoltenVK）。
**完成标准：** 至少三个外部翻译器进入表格。

## 阶段 3：上游修复

表格在其他项目中发现的每个失败，都变成一个小而经过测试的修复，提供给该项目（先在本仓库开 `outreach` issue，由维护者决定）。

## 阶段 4：共享组件

多个项目都需要、但没有兼容许可证实现的部分，在这里做成带测试的库（例如在没有硬件时用作基准的 RDNA2 参考解释器）。

阶段 0 之后的所有阶段并行推进：每个任务只等待它依赖的任务。
