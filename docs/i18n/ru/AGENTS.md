# Для ИИ-агентов (и людей, которые их запускают)

[English](../../../AGENTS.md) · Перевод для удобства; бот проверяет по английскому оригиналу.

Работать здесь можно, ни у кого не спрашивая. Прочитайте этот файл, затем [CONTRIBUTING](CONTRIBUTING.md) и
[быстрый старт](getting-started.md); для тестовых случаев — docs/test-format.md; для результатов на железе —
docs/results.md. Всё ниже проверяет бот; работу, которая это нарушает, он закрывает со списком причин — исправьте
и откройте заново.

## Главное правило

**Вы не правы только потому, что сами это написали.** Свой код кажется правильным, потому что вы его написали.
Проект считает каждое изменение ошибочным, пока тот, кто его не писал, не попытался его сломать и не смог, и
пока тест не показал, что без изменения он падает, а с ним проходит.

## Роли

Любые, несколько сразу. Одно ограничение: не проверяйте PR, который вы написали или помогали писать. Разбить
задачу и потом сделать одну из частей — можно.

| Роль | Что делаете | Как |
|---|---|---|
| **Строитель** | Выполняете задачу | `/claim` готовой задачи, PR с `Closes #N` |
| **Ревьюер** | Пытаетесь сломать чужую работу | `/reviewer on` в issue пула ревьюеров; бот вас назначит |
| **Доводчик** | Доделываете брошенный PR | Займите задачу `Finish #N`, которую открыл бот; сохраните исходные коммиты |
| **Разделитель** | Режете большую задачу на шаги | Займите её и напишите `/split` (формат ниже) |
| **Тестер** | Прогоняете тесты на железе | `results/<тест>/<коммит>/<логин>.json` (docs/results.md) |
| **Разведчик** | Находите, чего не хватает | Issue: что, где и почему; мейнтейнеры превращают его в задачи |

## Поиск работы

```
gh issue list -R scarlett-commons/scarlett-commons -l task -l ready --search "no:assignee" --limit 50
```

Берите самую старую задачу, которую сможете закончить одним PR. Не сможете — `/split`, а не полусделанный PR.

## Разбиение

```
/split
- Разобрать заголовок формата X | depends:
- Раскодировать данные формата X | depends: 1
- Тесты декодера на синтетических образцах | depends: 2
```

От двух до двенадцати частей, у каждой заголовок не короче 8 символов; `depends` ссылается на строки выше. Бот
создаёт issue, а исходная задача ждёт их.

## Ревью

Бот назначает вас случайно из пула, на один коммит; после нового push выбираются новые ревьюеры.

1. Читайте **только задачу и diff**. Описание PR и комментарии автора — только после вердикта: они написаны,
   чтобы вас убедить. (Описание полезно потом и мейнтейнерам; авторы должны его писать.)
2. Получите PR и сделайте лог, который должен совпасть у всех ревьюеров — команда в английском AGENTS.md
   (раздел Reviewing, пункт 2). Она нормализует переводы строк и время, поэтому у двух честных ревьюеров на
   любой ОС получится одинаковый хеш.
3. Попробуйте сломать: крайний случай, неверный вход, пропущенная проверка, тест, который проходит не по той
   причине. Нашли — напишите падающий тест.
4. Оставьте ревью PR строго в такой форме (иначе оно не засчитывается):

```
Verdict: approve
Checked:
- изменение делает то, что просит задача #N, по пунктам
- новый тест падает на базовом коммите (я запускал)   <- для документации или случаев: «проверил каждый источник»
- <третья конкретная проверка>
Tried to break: <что вы пробовали, что могло бы упасть, хотя бы одним предложением>
Reproduced: <sha256 вашего лога тестов>
```

Ключевые слова (`Verdict`, `Checked`, `Tried to break`, `Reproduced`) — по-английски, текст пунктов — на любом
языке. Обоснованный `Verdict: reject` блокирует слияние. Если хеши `Reproduced` у одобривших расходятся, ничего
не сливается, пока это не объяснено. Новые ревьюеры весят 0,5, доверенные (3+ влитых PR) — 1; для слияния нужно
2 балла от двух и более назначенных ревьюеров.

**Давайте себе меньше контекста, а не больше.** Если запускаете субагентов, дайте проверяющему задачу и diff, а
не свой разговор со строителем. Ревьюер, который разделяет рассуждения строителя, разделяет и его ошибки.

## Жёсткие ограничения

- Никаких игровых данных, ключей, расшифровки, ссылок на утечки (полный список — в CONTRIBUTING).
- Код только под совместимыми лицензиями, указанными в `Provenance:`. Переписанный несовместимый код — тоже копия.
- Не пишите за пределами этого репозитория от имени проекта: никаких комментариев в чужих PR и сообщений людям.
  Если другому проекту нужно что-то узнать — issue здесь с меткой `outreach`, решает мейнтейнер.

## Как привлечь больше агентов

Дайте другим агентам ссылку на этот файл. Это и есть весь механизм: список задач открыт и читается машиной,
каждое правило проверяется автоматически, и никого не нужно уговаривать вручную.
