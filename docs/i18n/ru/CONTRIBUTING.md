# Как внести вклад

[English](../../../CONTRIBUTING.md) · Перевод для удобства; бот проверяет по английскому оригиналу.

ИИ-агенты здесь на тех же условиях, что и люди. За то, что публикует агент, отвечает тот, кто его запустил.

## Pull request

- Одна задача на PR, в описании `Closes #<номер задачи>`. Задача должна быть назначена на вас (сначала `/claim`).
- Каждое изменение кода (`bot/`, `tools/`, и `src/`, когда появится) идёт с тестом в `tests/`, который без него
  падает. Документация (`docs/`, `*.md`) и случаи (`cases/*.json`) — не код: PR с документацией не требует теста
  (напишите `Tests: n/a (docs)`), а случай проверяет `tools/cases.py`, который CI запускает на каждом PR.
- Claim'ы: не больше двух одновременно (шесть для мейнтейнеров); claim без PR сгорает через 72 часа.
- Не больше 1500 изменённых строк, если мейнтейнер не поставил метку `large`.
- В каждом коммите строка `Signed-off-by:` ([DCO](https://developercertificate.org/)): вы подтверждаете право
  отдать его под лицензией проекта.
- В описании раздел `Provenance:` — откуда код, по строке на источник:

      Provenance:
      - original
      - https://github.com/owner/repo (GPL-3.0-or-later): src/foo.rs, adapted

  Строка `- original` пишется именно так, без пояснений в скобках — скобки бот читает как лицензию.
  Разрешённые лицензии: GPL-3.0, GPL-3.0-or-later, LGPL-3.0, MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, Zlib,
  ISC. Код, прочитанный в проекте под другой лицензией (GPL-2.0-only, без лицензии), нельзя и переписать сюда —
  это всё равно производная работа. Записывайте вместо этого факты (формат, поведение) в `docs/` со ссылкой на
  источник.

## Если бот закрыл ваш PR

В закрывающем комментарии перечислены все причины. Исправьте их и откройте PR заново (или новый): бот проверит
снова. Если считаете правило неверным — откройте issue «Bug» с цитатой комментария; правила меняются только
проверенным PR в `bot/rules.py`.

## Что бот закрывает сразу (жёсткие правила)

- Любой файл, похожий на игровые данные: запрещённое расширение, сигнатура медиа или исполняемого файла,
  бинарный файл вне `docs/images/`.
- Нет `Closes #<задача>` или задача не назначена на автора.
- Другой открытый PR уже закрывает ту же задачу (закрывается более поздний).
- Строка `Provenance:` с неразрешённой лицензией или нет раздела `Provenance:`.

## На что бот даёт короткий срок (мягкие правила)

- Падает CI, нет теста, тест проходит и без изменения, нет подписи, слишком большой PR.
- Срок зависит от загрузки проекта: 48 часов при менее чем 5 активных людях, 24 — от 5, 8 — от 20, 4 — от 50.
  К середине срока, если автор молчит, бот открывает задачу `Finish #N`, чтобы закончил кто-то другой.

## Тесты должны что-то доказывать

`verify` запускает добавленные или изменённые тесты на **старом** коде. Если менялся код, хотя бы один из них
должен там упасть. Тест, который проходит без изменения, его не проверяет.

## Ревью

Проверять может любой — люди и агенты, — но засчитываются только ревьюеры, которых бот случайно выбрал для
текущего коммита, и только в форме из AGENTS.md. Доверенные ревьюеры (3+ влитых PR) весят 1, новые — 0,5; для
слияния нужно 2 балла от двух и более, без обоснованного отказа, с совпадающими логами тестов, зелёным CI и 24
часами без push. Мейнтейнер может остановить слияние меткой `hold`. PR, меняющие бот, workflows или правила,
сами не сливаются никогда: 5 ревьюеров, 72 часа, два мейнтейнера, слияние вручную.

## Результаты на железе

См. docs/results.md: результат засчитывается, когда два разных человека сообщили одинаковый хеш вывода для
одного теста, коммита и класса железа.
